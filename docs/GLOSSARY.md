# BSI Messenger Glossary & Terminology

## Overview

This glossary defines terms, acronyms, and concepts used throughout BSI Messenger documentation and codebase.

---

## A

**Access Token**  
Short-lived JWT token (typically 15-30 minutes) used to authenticate API requests. Automatically refreshed before expiry.

**ACK (Acknowledgment)**  
Server confirmation that a message was received and stored. Contains the server-assigned message ID and sequence number.

**Admin**  
User account type with full system privileges including user management, configuration, and access to admin panel.

**Agent**  
User account type designated for customer service operations in omnichannel messaging (future feature).

**API (Application Programming Interface)**  
RESTful HTTP interface for data operations. Base URL: `/api/`

**AppImage**  
Linux application packaging format. Self-contained executable that runs on most distributions without installation.

**Attachment**  
File associated with a message (images, documents, audio). Stored in MinIO object storage with metadata in database.

**Auth Store**  
Zustand store managing user authentication state, session tokens, and login/logout operations.

**Avatar**  
User profile photo. Stored as MinIO object with key reference in User table. Falls back to initials if not set.

---

## B

**Backend**  
Express.js server providing REST API, WebSocket server, and business logic. Runs on `chat.bsilongevity.com:4443`.

**BigInt**  
JavaScript type for large integers. Used for message sequence numbers to prevent overflow in high-volume conversations.

**Blob URL**  
Temporary browser URL (`blob://...`) referencing in-memory data. Used for image preview during upload and caching.

**Broadcast**  
Planned feature for sending messages to multiple recipients simultaneously via WhatsApp Business API.

---

## C

**Call**  
Audio or video communication session between users. Uses LiveKit SFU architecture for media streaming.

**Call Store**  
Zustand store managing call state machine, media streams, and call controls (mic, camera).

**Capacitor**  
Framework for building cross-platform mobile apps with web technologies. Enables native functionality on Android/iOS.

**Chat Store**  
Zustand store managing conversations, messages, and real-time updates via WebSocket.

**clientMsgId**  
Unique identifier generated by client for message tracking. Used for optimistic updates and server ACK matching.

**CORS (Cross-Origin Resource Sharing)**  
Browser security mechanism. Avoided in desktop app via local proxy server making all requests same-origin.

**Conversation**  
Communication channel between users. Can be DIRECT (1-on-1) or GROUP (multiple participants).

**ConvType**  
Enum: `DIRECT` or `GROUP`. Determines conversation behavior and UI presentation.

---

## D

**DM (Direct Message)**  
One-on-one conversation between two users. Equivalent to DIRECT conversation type.

**DND (Do Not Disturb)**  
User status indicating they don't want to receive notifications. User is online but appears busy.

---

## E

**Electron**  
Framework for building desktop applications using web technologies. Provides native OS integration and Node.js access.

**ERD (Entity Relationship Diagram)**  
Visual representation of database schema showing tables, columns, and relationships.

---

## F

**FCM (Firebase Cloud Messaging)**  
Google service for push notifications on Android and iOS. Integrated via Capacitor plugin.

**Functional Component**  
React component written as function. Modern standard replacing class components.

---

## G

**Gatekeeper**  
macOS security feature requiring app notarization. Apps must be signed and notarized to run on macOS 10.15+.

**getUserMedia**  
Browser API for accessing camera and microphone. Used for audio/video call media streams.

---

## H

**HMR (Hot Module Replacement)**  
Development feature allowing code changes to reflect instantly without full page reload. Preserves application state.

**Hook**  
React function (starting with `use`) for adding state and lifecycle to functional components. Examples: `useState`, `useEffect`.

---

## I

**IPC (Inter-Process Communication)**  
Communication mechanism between Electron main and renderer processes. Uses `ipcMain` and `ipcRenderer` with context bridge.

---

## J

**JWT (JSON Web Token)**  
Compact, URL-safe token format for authentication. Contains encoded user claims and expiry timestamp.

---

## L

**LiveKit**  
Open-source WebRTC SFU server for real-time audio/video communication. Handles media routing, NAT traversal, and quality adaptation.

**Local Proxy**  
HTTP server running on `127.0.0.1` in Electron app. Forwards API/WebSocket requests to backend, providing same-origin context.

---

## M

**Main Process**  
Electron's Node.js process with full system access. Manages windows, system integration, and IPC handlers.

**Member**  
User participating in a conversation. Has role (OWNER, ADMIN, or MEMBER) determining permissions.

**MemberRole**  
Enum: `OWNER`, `ADMIN`, `MEMBER`. Defines user's permissions within a group conversation.

**MessageType**  
Enum: `TEXT`, `IMAGE`, `FILE`, `AUDIO`, `SYSTEM`, `CALL`. Determines message rendering and behavior.

**MinIO**  
S3-compatible object storage for files and avatars. Accessed via pre-signed URLs or authenticated requests.

**Moderator**  
User account type with elevated privileges for content moderation and user management.

---

## N

**NAT (Network Address Translation)**  
Router feature complicating peer-to-peer connections. LiveKit SFU architecture solves NAT traversal issues.

**Notarization**  
Apple process for malware scanning. Required for macOS apps to run on 10.15+ without security warnings.

**NSIS (Nullsoft Scriptable Install System)**  
Windows installer framework used by Electron Builder. Creates `.exe` installers with custom options.

---

## O

**Optimistic Update**  
UI pattern showing result immediately before server confirmation. If server rejects, update is rolled back.

**Omnichannel**  
Future feature for unified inbox handling messages from multiple platforms (WhatsApp, Instagram, webchat).

---

## P

**P2P (Peer-to-Peer)**  
Direct connection between clients. Not used in BSI Messenger due to NAT/firewall issues. SFU preferred.

**Payload**  
Data content of a message or event. JSON object containing relevant information for the event type.

**Ping/Pong**  
WebSocket heartbeat mechanism. Client sends ping every 30s, expects pong within 70s to verify connection.

**PostgreSQL**  
Relational database system. Version 16.14 used for storing users, messages, conversations, and sessions.

**Preload Script**  
Electron script running in renderer context with Node.js access. Creates secure IPC bridge via `contextBridge`.

**Presence**  
Real-time user status information. Updated via WebSocket events when users change availability.

**Proactive Refresh**  
Token refresh scheduled 60 seconds before expiry. Prevents auth interruption during active usage.

---

## R

**React Query**  
Data fetching library for server state management. Handles caching, background updates, and request deduplication.

**Reactive Refresh**  
Token refresh triggered by 401 error. Fallback when proactive refresh fails or token expires unexpectedly.

**Read Cursor**  
Sequence number of last message read by user in conversation. Used for unread count and read receipts.

**Read Receipt**  
Indicator that recipient has read a message. Sent via WebSocket when user views conversation.

**Redis**  
In-memory data store used by backend for session management and caching.

**Refresh Token**  
Long-lived token (days/weeks) used to obtain new access tokens. Stored securely, revoked on logout.

**Renderer Process**  
Electron's Chromium browser process. Runs React app with limited system access for security.

---

## S

**SFU (Selective Forwarding Unit)**  
Media server architecture routing streams efficiently. LiveKit uses SFU for scalable video conferencing.

**Seq (Sequence Number)**  
Auto-incrementing number per conversation. BigInt type ensures unique ordering even in high-volume chats.

**Session**  
Active user authentication. Tracked in database with refresh token and expiry. Multiple sessions allowed per user.

**Sidebar**  
Left panel showing conversation list, search, and user controls.

**Store**  
Zustand state container. Three main stores: auth, chat, call. Provides global state management.

**Supervisor**  
User account type for managing customer service agents (future omnichannel feature).

---

## T

**TailwindCSS**  
Utility-first CSS framework. Provides low-level utility classes for rapid UI development.

**TanStack Router**  
Type-safe routing library for React. Provides file-based routing with automatic code splitting.

**Template**  
Pre-approved message format for WhatsApp Business API (future feature). Required for outbound marketing messages.

**Tray Icon**  
System tray (Windows/Linux) or menu bar (macOS) icon. Provides quick access when window is hidden.

**TypeScript**  
Typed superset of JavaScript. Provides compile-time type checking and enhanced IDE support.

**Typing Indicator**  
Real-time notification that user is composing a message. Throttled to prevent excessive WebSocket traffic.

---

## U

**UserStatus**  
Enum: `AVAILABLE`, `AWAY`, `DND`, `OFFLINE`. Indicates user's current availability.

---

## V

**Vite**  
Modern build tool and dev server. Provides instant HMR and optimized production builds.

**Virtuoso**  
React component for efficiently rendering large lists. Used for message history with thousands of items.

---

## W

**WebRTC (Web Real-Time Communication)**  
Browser API for peer-to-peer media streaming. Used by LiveKit for audio/video calls.

**WebSocket**  
Protocol for persistent bidirectional communication. Used for real-time message delivery and presence updates.

**WS_URL**  
WebSocket endpoint URL. `wss://chat.bsilongevity.com:4443/ws` for production, proxied in development.

---

## Z

**Zustand**  
Lightweight state management library. Simpler than Redux, uses hooks for component subscription.

---

## Technical Patterns

**Exponential Backoff**  
Retry strategy where delay doubles after each failure. Used for WebSocket reconnection (3s → 6s → 12s → max 30s).

**HMR-Safe Code**  
Code that properly cleans up resources during hot reload. Prevents memory leaks and duplicate event listeners.

**Optimistic UI**  
Show expected result immediately while waiting for server. Improves perceived performance.

**Same-Origin Policy**  
Browser security preventing cross-origin requests. Local proxy makes all requests same-origin.

**Type Guard**  
TypeScript function that narrows type based on runtime check. Example: `typeof x === 'string'`
